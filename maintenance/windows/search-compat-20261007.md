# 恢复普通关键词搜索中的旧索引条目（2026-10-07）

用户复现：旧官方版能搜索“鬼父”，取消 nsfw 参数后的定制版仍不能。

调查证据：当前使用直连，本机保存的 Bangumi 令牌有效（用户接口 HTTP 200），但收藏同步关闭时普通请求不发送该令牌。诊断另行携带令牌，仅请求官方 api.bgm.tv，未输出令牌或账号信息。无令牌和有令牌、nsfw 省略/null/true/false 的新版搜索均未返回目标条目（33504），均为 208 条结果且首屏无 NSFW。因此仅改 nsfw 或补发当前令牌都不足以解决。旧公开关键词接口返回“鬼父”、续作及普通条目，实际分页 offset 0/20/40 返回不同结果。

最小兼容调整：有关键词、无高级过滤、默认排序的普通搜索优先使用 `/search/subject/{keyword}`，映射旧接口的日期、评分和排名字段。标签、日期、排名范围、评分范围、星期及非默认排序保留新版搜索。旧接口错误或不兼容时回退新版。旧索引页面会省略部分条目，分页按源页面宽度前进。

限制：旧接口属于兼容接口，将来可能不可用；新版详情与评论接口仍可能拒绝部分索引条目，不能声称全面恢复所有 R18 详情或高级搜索。现有详情页会保留搜索传入的基础资料，不改动验证码、@self 或视频解析逻辑。

验证：先写回归测试，确认原实现不能返回 33504，再修改；31 项搜索、收藏同步及参数测试通过。使用生产搜索代码、隔离临时设置和真实网络确认“鬼父”（33504）及“进击的巨人”（55770）均返回。静态分析仍为 17 info / 0 warning / 0 error。十个 hanime1 文件与三份外部补丁核验一致。Release 构建成功。

程序目录：`<local release>`。桌面 Kazumi 入口切换至此目录。替换前程序及用户数据保存于 `<local backup>`；此前 Release 目录及标签均保留。
